# 定义对局领域模型与状态机

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 01

## Question

MVP 应采用哪些统一领域术语和确定性状态转换来表达座位、角色牌、影响力、回合、行动、声明、质疑、阻挡、揭示、换牌、淘汰与获胜，并如何消除所有时序歧义，使同一输入总能得到同一合法结果？

## Answer

采用“权威快照 + 经校验的命令 + 追加事件日志”的确定性对局核心。统一领域语言见 [`CONTEXT.md`](../../../CONTEXT.md)；其中“影响力”特指仍面朝下的一张角色牌，“证明”与失去影响力时的“揭示”是不同概念。

### 权威状态

`MatchState` 至少表达：

- 对局状态（设置中、进行中、已结束）、状态版本、随机种子标识和胜者；
- 固定座位顺序、当前回合座位、各座位的钱币、角色牌及淘汰状态；
- 宫廷牌库中的牌；
- 当前待处理行动（行动者、类型、目标、角色声明及费用状态）；
- 当前角色声明、响应窗口、按顺时针排列的待响应座位；
- 尚待完成的证明、影响力揭示或交换选择。

状态版本随每次成功命令递增。命令必须携带预期版本；重复、过期、越权或在错误阶段提交的命令不改变状态。

### 外部命令

核心只接受当前阶段明确允许的命令：

- `DeclareAction`：声明行动并同时指定必要目标；
- `ChallengeClaim` / `PassChallenge`：质疑或放弃质疑；
- `DeclareBlock` / `PassBlock`：声明阻挡或放弃阻挡；
- `ProveClaim` / `ConcedeClaim`：被质疑者证明角色或主动认输；
- `ChooseInfluenceToReveal`：选择失去哪一点影响力；
- `ChooseExchangeCards`：大使交换时选择归还的两张牌。

阶段推进、洗牌、抽牌、转移钱币、淘汰检查和开启下一回合均由核心自动执行，不由前端或 Agent 直接命令。

### 状态转换

主流程固定为：

1. `AwaitAction`
2. 若行动包含角色声明，进入 `AwaitActionChallenge`
3. 必要时进入 `AwaitClaimDefense` 与 `AwaitInfluenceReveal`
4. 若行动仍有效且允许阻挡，进入 `AwaitBlock`
5. 有人阻挡时进入 `AwaitBlockChallenge`
6. 必要时再次进入 `AwaitClaimDefense` 与 `AwaitInfluenceReveal`
7. `ResolveAction`
8. 检查终局；否则前进至下一名未淘汰座位并回到 `AwaitAction`

大使交换在行动结算中进入 `AwaitExchangeSelection`，选择完成后才结束回合。

### 确定性约定

- 每个质疑或阻挡窗口从声明者的下一名未淘汰座位开始，按顺时针逐席询问；第一个提交有效响应者取得响应权。其他座位不再响应。
- 所有人放弃后窗口永久关闭，不能追溯响应。
- 阻挡声明被成功质疑后，不重新开放阻挡窗口，直接继续结算原行动。
- 被质疑者即使实际持有匹配角色，也可以选择 `ConcedeClaim`；只有选择 `ProveClaim` 才展示、洗回并抽取替代牌。
- 刺杀的 3 枚费用在声明时预留。行动角色声明被成功质疑则退回；声明未被推翻后正式支付，所以后续被伯爵夫人阻挡也不退。
- 每次影响力损失后立即检查淘汰和胜负。若目标已因质疑失败失去最后一点影响力，原刺杀不再造成额外损失。
- 每局由隐藏种子驱动洗牌和补牌，事件记录实际随机结果，以支持完整回放和确定性测试。
- 数字版国库是钱币来源与回收处，不把盒内 50 枚实体钱币作为硬上限；官方未定义“国库耗尽”行为。
- 动画时长、Agent 思考时间、网络延迟和非约束性桌边交流不属于权威规则状态。

### 必须保持的规则不变量

- 基础牌组始终只有五种角色各三张；每张角色牌在任一时刻只位于一个座位、宫廷牌库或已揭示区域。
- 存活座位有一至两张面朝下角色牌；淘汰座位没有面朝下角色牌且不能再提交游戏命令。
- 钱币数始终为非负整数；钱币、已揭示牌和淘汰状态均为公开信息。
- 回合开始时当前座位有 10 枚或更多钱币时，唯一合法行动是政变。
- 角色行动先处理行动声明的质疑，再处理阻挡及其质疑，不能倒序或回溯。
- 只剩一个未淘汰座位时立即结束对局，不再开启下一阶段或下一回合。
