# 定义对局创建与 Agent 配置体验

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 02, 04, 07

## Question

用户应如何选择 2–6 人总座位数，并为每个 AI 座位选择 OpenCode 或 Claude、具体模型及必要配置？系统如何在开局前发现能力、验证可用性并清楚提示配置问题？

## Answer

开局采用单页配置，视觉风格与策划桌一致。MVP 明确为**本机自用**：复用本机已安装 OpenCode / Claude Code 的登录状态，应用内不配置、不存储 API key；设置页与开局页标注该边界。

### 配置流程

1. 选择总人数 2–6。
2. 座位 1 固定为本地玩家，不可改为 Agent，也不可删除。
3. 其余座位自动生成显示名（如灰狐），并按座位列表顺时针排列；本地玩家固定先手。
4. 每个 AI 座位独立选择 CLI（OpenCode 或 Claude Code），再从该 CLI 运行时发现的模型列表中选择具体模型。
5. 模型列表展示可读名称，提交与持久化使用稳定模型 ID；不同座位可选用相同或不同的 CLI/模型。

### 能力发现与就绪校验

- 进入开局页时，本地服务自动探测：CLI 是否在 PATH 中、版本是否受支持、认证是否就绪、可用模型列表。
- 探测不读取或回传任何令牌、Cookie、账号标识或密钥；浏览器只收到脱敏状态与模型目录。
- 每个 AI 座位显示状态：就绪、未安装、版本不支持、未认证、无可用模型、所选模型已失效。
- 提供“重新检测”。任一 AI 座位未就绪时禁用“开始对局”，并给出可操作提示（例如先在终端完成对应 CLI 登录）。
- 点击开始时再做一次轻量复检；通过后创建对局并进入策划桌对局界面。

### 记忆与边界

- 上次人数、各座位 CLI 与模型选择写入 SQLite 非敏感设置；下次进入预填，但仍重新探测就绪状态。
- 开局页不配置 Agent 人设、策略提示词、工具权限或预算；这些若需要，由后续“定义 Agent 策略配置与可玩质量”决定。
- 若用户将来对外分发本应用，必须另行改为受支持的 API key / 云 provider 方案；本机订阅登录态仅限当前自用 MVP。
