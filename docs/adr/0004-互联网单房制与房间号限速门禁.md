# 互联网单房制与房间号限速门禁

产品从局域网联机转为互联网联机后，房间门禁形态随之改变。

## 背景

局域网时代，规格明确「不能只靠房间号加入」：房间号只是弱门禁，必须配合可指向主机的链接或「IP:端口 + 房间号」，否则弱门禁会在未指向主机时被误用。转为公网后，入口固定为同一站点（先 IP:8787，后域名），「指向主机」这一步失去意义；同时 4 位数字房间号（1 万种组合）在公网上可被脚本穷举。

## 决策

- **单房制**：服务器同一时刻只存在一个房间，创建新房会解散旧房。房间号退化为对唯一一桌的「暗号」，客人输入房间号即加入该桌；输错与「房主尚未开房」统一提示「房间号不正确，或房主还没开房」，二者不可区分也不需区分。
- **纯房间号加入**：加入页只有一个 4 位数字输入框；废除「禁止仅凭房间号加入」的旧规则；旧的 `/join?code=####` 链接仍兼容，自动预填输入框，但不提供链接 UI。
- **限速防穷举**：对按房间号查询失败的请求按来源 IP 限速（每 IP 每分钟约 10 次失败尝试），把穷举从分钟级拖到小时级，配合「房间随手开随手散」的用法足够；不做更重的强门禁。
- **不做多房制**：多人同时开两桌以上不是当前产品场景；多房制要求房间注册表、对局存储、当前对局路由、恢复与离席追踪全部按房间维度改造，工程代价是量级的。

## 备选

- 多房制：被否决，见上。
- 加长/字母房间号：防爆破收益有限，伤害口头分享体验。
- 无任何防护：被否决，脚本可秒级进房捣乱。
