# ADR-0013: 卡坦岛接入平台栈与 AI 队友座位

日期：2026-09-05
状态：已采纳

## 背景

卡坦岛先以纯前端 Mock 原型落地（视觉与交互先行，引擎为 `apps/web/src/catan/mock/`
纯函数，无后端）。用户随后明确两点：一是**联机化**——参考已有三款游戏复用平台层，
不需要纯前端形态；二是给 coup/brass/splendor 增加 **AI 队友模式**，一个人也能玩。

平台层（ADR-0010）已把房间/座位/心跳/计时/续局/恢复收敛为 GameModule 接缝，
其中座位模型是纯人类的：`local_human | remote_human`，超时代打只服务人类超时。

## 决策

1. **卡坦岛联机化走标准接入清单**：
   - 规则引擎独立成包 `packages/catan-domain`（Mock 引擎原样提升）：纯函数、无 IO，
     `applyCommand` 原子命令协议（roll/建造/发展卡/强盗/交易/end_turn 14 条），
     `projectForSeat` 座位投影（他人手牌与发展卡身份隐藏、仅留 `handCount/devCount`，
     牌库顺序剥离、`lastDice` 公开）。每次成功命令 `stateVersion` 递增。
   - 服务器 `apps/server/src/catan/`（catanModule / catanRuntime / catanStore），
     `catan_rooms` / `catan_runs` 两张独立表，逐命令落库。
   - 前端 `catanApi.ts`（`createRoomClient("catan")` 薄壳）+ CatanApp 房间流程
     （home/room/play，与 BrassApp 同构）+ CatanTable 改吃服务端投影视图；
     Mock 阶段的本地引擎与 AI 调度（`mock/`、`useCatanGame`）删除。
   - 联机化过程补了两处 Mock 阶段不需要的规则收紧：**强盗每阶段限挪一次**
     （`robberMoved` 标记，否则原始命令通路可反复挪强盗刷劫）；终局冻结全员明分
     （`finalScores`，投影态无法算他人隐藏的胜利点卡分）。

2. **AI 队友做成平台层能力，而不是各游戏私搭**：
   - `LobbySeatKind` 增加 `"bot"`：房主在大厅把空位配置为 bot
     （`PATCH …/seats/:id/config {kind:"bot"}`，命名「机器人·甲乙丙…」）。
     bot 座位不可认领、无凭证、不参与心跳与空房回收判定
     （`seatFacts` 投影为 `controller:"other"`——该值原本就存在且被平台忽略）。
   - `GameModule` 增加可选钩子 `planBotDecision(state, seatId)`：平台栈在
     「欠决策座位是 bot」时延迟 0.9–2.2 秒出一条命令，经 `submitDecision`
     与人类完全同通路提交（持久化、事件、`autoDecision` 标记全部一致）。
     成功后按新状态续链；bot 规划器没覆盖的阶段用 `planAutoDecision` 兜底一次；
     再失败则停链（交给回合计时器），避免无状态死循环。
   - 驱动点覆盖：开局、人类决策后、超时代打后、强制淘汰后、**重启恢复后**；
     `dissolveRoom` 与技术中止时清 bot 计时器。测试注入口
     `botDecisionDelayMs`（集成测试传 `() => 5`）。
   - 座位→游戏内玩家的映射进各域状态并随 run 快照持久化：brass/splendor 用
     `state.botPlayers?: number[]`（旧快照缺省视为无），coup 复用域里既有的
     `stub_agent` 座位控制器（早期「联网去 agent」留下的类型被重新启用），
     catan 用 `PlayerState.isHuman`。**投影必须透传 botPlayers**——
     splendor 的 `SplendorPublicState` 是显式字段对象，这次就漏过一次。
   - coup 的提交通路新增 `submitAgentDecision`（仅接受 `stub_agent` 座位；
     HTTP 决策路由只认人类凭证，永远到不了这里）。

3. **各游戏 bot 启发式都放进服务器侧、全部确定性或轻量随机**：
   - catan：`catan-domain/autoPlan.ts`，城→村→路→发展卡优先级 + 强盗压对手
     高产出格 + 交易按富余度回应；引擎单测含「四机器人全自动对局在合理步数内
     分出胜负且中途无卡死」回归。
   - brass：`brassRuntime.planBrassBot`，建造→铺路→贷款→跳过的贪心
     （与大厅陪玩脚本 lobbybot.mjs 同思路，但运行在服务端权威态上），
     资源来源就近私矿/工场优先、市场兜底。
   - splendor：`planSplendorBot`，买分牌优先→按缺口拿宝石→预留关键牌；
     弃牌/选贵族交给既有超时代打计划。
   - coup：`games/coupBot.ts`，从该座位 `legalDecisions` 里按
     政变（≥10 强制）→收税→偷最富→刺杀高影响→收入 挑选；防御上只拦偷窃、
     不轻信挑战、被抓自认。全部决策来自合法集，保证合法性。

4. **掉库教训（同族第二种形态）**：catanModule 最初按 brass 的样子以
   `newEvents.length === 0` 跳过落库——但 catan 存在**状态有变而不产生事件**
   的命令（婉拒交易、结束挪强盗），`stateVersion` 已递增却没写库，重启回滚。
   修复为凡成功命令一律 `commitCommand`，并以「重启恢复后版本不回退」
   集成测试锁定（`catanRoomApi.test`）。判据记牢：**有没有事件 ≠ 有没有状态变化**。

5. **对局中「离开」的语义**：房间 phase 在对局中恒为 `match`，从对局桌面
   返回房间大厅会被大厅轮询弹回对局。卡坦的「离开」因此定为回首页，
   房间凭房号/邀请链接可重进；平台侧本就不提供「凭会话杀局」（ADR-0012）。

## 结果

- 四款游戏（coup/brass/splendor/catan）大厅均有一键「加AI/撤下AI」；
  卡坦首页「开始游戏」= 建房 + 三个 AI 衡位 + 直接开局，一个人即可完整体验。
- bot 行动与人类决策同通路：事件、持久化、`autoDecision` 展示标记、
  重启恢复后续玩，全部复用既有语义，平台栈新增代码约 80 行。
- 测试基线 296 → 307：catan-domain 18（含全自动对局回归）、
  server 115 → 121（catanRoomApi 3 项 + botSeatApi 3 项，后者覆盖三款游戏 bot 驱动）。
