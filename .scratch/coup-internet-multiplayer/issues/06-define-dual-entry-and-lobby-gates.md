# 钉死双入口与大厅配置开局门禁

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 01

## Question

在「双入口、主机独掌大厅配置与开局、客人只改己名并占空人类位、未满可开但不得留下仍标等待人类的空位」已定的前提下，本机对战与局域网主机模式的切换时序、大厅座位槽状态机（空位/远程人类/本机 Agent）、开局前就绪门禁（含 Agent 探测）以及与现有本机开局页的复用边界应如何写进规格？

## Answer

- **模式切换**：启动默认本机对战（loopback + 现有随机端口行为）。用户选「创建房间」进入主机模式时：重绑 `0.0.0.0`（端口策略见 [钉死房间码格式与加入链接形态](04-define-room-code-and-join-link.md)），浏览器导航到 LAN Origin，再进大厅。回到本机对战须先解散房间再切回 loopback。
- **座位槽**：座位 1 固定本地人类（主机）。其余槽由主机设为 **开放占座** / **本机 Agent**（CLI+模型，复用探测）/ **关闭**。远程人类占座后槽变为已占；客人可改自己显示名。
- **首页**：三入口——本机对战、创建房间、加入房间。本机开局页与大厅配置分离，不共用同一表单；Agent 控件仅出现在本机页与大厅 Agent 槽。
- **开局门禁**（仅主机可见开始按钮）：有效座位数（本地人类 + 已占远程人类 + Agent，不含关闭槽）为 2–6；无仍为「开放占座」的空槽；每个 Agent 槽能力探测就绪（可重新检测）；点开始时服务端复检。不强制至少一名远程人类已占座。
