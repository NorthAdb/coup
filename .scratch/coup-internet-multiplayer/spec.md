# 《政变》互联网联机规格

## Problem Statement

单机 MVP 已能在本机与 Agent 对弈，局域网房间也已支持多人在线。现在把联机形态收敛为**互联网多人对局**：部署在云服务器上，2–6 名真人凭 4 位房间号加入同一房间打完整局；**联机不提供 Agent 座位**，Agent 对战只留在本机单机版。产品由此拆分为两块独立应用：联机版（部署到云）与本机版（仅本机使用），两块代码不纠缠。

## Solution

- **联机版**：`apps/web` + `apps/server`。首页只有「创建房间 / 加入房间」；创建房间后获得 4 位房间号，客人**只凭房间号**加入；单房制（同一时刻一桌）；座位 2–6 全为真人（开放占座 / 关闭），无 Agent、无链接、无网卡选择。
- **本机版**：`apps/web-local` + `apps/server-local`。只保留本机人类 + 本机 Agent 对战（loopback），无任何房间代码。
- **共享层**：`packages/domain`（规则引擎）、`packages/protocol`（协议类型）、`packages/web-desk`（策划桌 UI）。
- 房间内的对局、占座/回席/离席/处置、主机重启恢复机制沿用局域网时期的成熟实现，仅去掉 Agent 相关项。

## User Stories

1. As a 主机, I want 在首页点「创建房间」就在当前地址直接开房并看到 4 位房间号, so that 我能把房间号发给朋友。
2. As a 主机, I want 一键复制房间号, so that 我能用聊天工具把号发出去。
3. As a 客人, I want 在首页点「加入房间」后只输入 4 位房间号即可加入, so that 我不必记 IP 或链接。
4. As a 客人, I want 输入错误的房间号时看到「房间号不正确，或房主还没开房」的统一提示, so that 我知道该找房主确认。
5. As a 系统, I want 对猜房间号的请求按 IP 限速, so that 4 位房间号不会被脚本秒级穷举。
6. As a 主机, I want 座位 1 固定为我的本地人类座位, so that 主机身份清楚。
7. As a 主机, I want 将其余座位设为开放占座或关闭, so that 我能限定桌人数（如 4 人桌关 5、6 号座）。
8. As a 客人, I want 占一个开放人类座位并修改自己的显示名, so that 我能入席且桌上可辨认。
9. As a 主机, I want 仅当有效真人座位 2–6 且无开放空槽时才能开局, so that 不会开到一半缺人；主机一人不能开局。
10. As a 远程人类, I want 断线后先有重连宽限再进入离席等待, so that 短暂闪断不立刻毁体验。
11. As a 主机, I want 离席超时后能继续等待、技术中止或强制揭示淘汰, so that 对局不会无人可推进（联机版无「换本机 Agent」）。
12. As a 远程人类, I want 凭座位凭证回席认回原座位, so that 刷新或重开页面后还能续玩。
13. As a 客人, I want 服务器进程消失时看到等待提示并在恢复后回席, so that 我知道该等还是该换房间。
14. As a 主机, I want 重启服务后恢复未结束的房间与对局（同一 run）, so that 崩溃不等于整局作废。
15. As a 主机, I want 恢复失败时得到明确提示并作废旧房后才能开新房, so that 不会静默顶替房间号坑客人。
16. As a 主机, I want 终局后在策划桌右上角「继续对局」进入续局等待, so that 同一房间同码续局，客人确认加入后才开新局。
17. As a 开发者, I want 联机版代码零 Agent 痕迹、本机版代码零房间痕迹, so that 两块互不纠缠、各可独立演进。
18. As a 用户, I want 旧 `/join?code=####` 链接仍可打开并自动填好房间号, so that 历史分享链接不失效。
19. As a 远程人类, I want 主机开启续局等待后收到弹窗选择「加入对局 / 离开对局」, so that 我能决定是否继续下一局，而非被直接拉入。

## Implementation Decisions

### 双应用拆分

- 联机版 `apps/web` + `apps/server`；本机版 `apps/web-local` + `apps/server-local`。见 `docs/adr/0005`。
- 共享：`packages/domain`、`packages/protocol`、`packages/web-desk`（策划桌 UI）。服务端对局编排按版本各持一份，Agent 路径只在本机版。
- 服务器版不提供「本机对战」入口；本机版保留完整 Agent 对战。

### 单房制与房间号门禁

- 同一时刻仅一房；创建新房解散旧房。见 `docs/adr/0004`。
- 房间号：4 位数字，创建时随机，冲突重抽。
- 加入：纯房间号（单输入框）；统一错误提示「房间号不正确，或房主还没开房」；`/join?code=####` 兼容预填。
- 防穷举：房间号查询失败按 IP 限速（每 IP 每分钟约 10 次失败尝试），成功后恢复。
- 不做多房制、不做强门禁、不做账号体系。

### 纯真人房间

- 座位 2–6 只允许「开放占座 / 关闭」；服务端拒绝任何 Agent 座位配置。
- 开局门禁：有效真人座位 2–6、无开放空槽；开局时服务端复检门禁。
- 离席处置：继续等待 / 技术中止 / 强制揭示淘汰（无「换本机 Agent」）。

### 域名入口

- 无域名阶段：访问 `http://IP:8787`；有域名后经反代访问域名。
- 服务端已是主机模式且请求 Origin 在放行名单内时，**直接在当前地址创建房间**，不做任何跳转；「重绑跳转」仅存在于本机版 loopback 场景。
- `COUP_PUBLIC_HOST`（展示主机）、`COUP_ALLOWED_ORIGINS`（放行 Origin）环境变量；有域名后指向域名与 `https://域名`。

### 会话、Origin 与座位凭证

- 按各客户端实际入口 Origin 维持精确 Origin + HttpOnly/`SameSite=Strict` Cookie + CSRF。
- 座位凭证与进程会话 Cookie 分离，绑定房间+座位，服务端存哈希；回席成功轮换。

### 离席、等待与主机处置

- 通道断开 → 15s 宽限（重连中，不因该座暂停）→ 离席 + 5min 软超时；座位卡显示状态与剩余时间。
- 若正轮到该座则决策点暂停；否则可继续至下次需要该座。
- 软超时本身不废凭证；回席成功轮换；淘汰/中止/终局/解散时作废。

### 主机重启恢复

- 大厅与已开局对局均持久化（房间号、槽位、占座、凭证哈希；已开局关联未结束 run）。
- 主机重启 = 继续同一 run（同一 `matchId`/事件序号）。
- 宕机期间冻结离席软超时；恢复后再给短宽限（15s）。
- 恢复失败：显式提示；放弃并作废旧房/凭证后才能开新房。

### 同房续局

- 终局后主机可「继续对局」进入**续局等待**（房间阶段 `rematch`），不立即开新局。
- 远程座位在续局等待中为「待确认」；客人弹窗选择**加入对局**（保留原座位、轮换凭证）或**离开对局**（座位转开放占座、凭证作废）。
- 终局凭证保留至续局等待结束；刷新页面的客人可认回原座位；待确认座位不可被持码陌生人抢占。
- 续局开局门禁：有效真人座位 2–6、无开放空槽、无待确认座位；不设自动超时，待确认/开放座位由主机手动改配。见 `docs/adr/0006`。

## Testing Decisions

- 对局规则核心在 `packages/domain`（继承自单机 MVP）；联机增量以编排/会话冒烟 + 关键谓词单测为主，不断言 UI 布局细节。
- 可自动化覆盖：房间号格式与冲突、开局门禁谓词（含同房续局门禁）、离席状态机计时（可注入时钟）、凭证绑定与轮换、恢复加载同一 `matchId`、房间号限速。
- 发布验收以下列清单为准。

### 验收清单（必过）

- 联机版首页只有「创建房间 / 加入房间」两入口；本机版无任何房间入口
- 创建房间后在同一地址显示大号房间号并可一键复制；无加入链接、无网卡选择
- 客人只输 4 位房间号即进入占座页；错误号统一提示且触发限速；`/join?code=` 兼容预填
- 座位 2–6 仅开放/关闭；无任何 Agent 痕迹（座位配置、探测、处置项）
- 开局门禁：有效真人 2–6、无开放空槽；主机一人不能开局
- 同机双浏览器 + 域名/IP 入口：占座、改名、开局、对局决策、座位凭证回席
- 断线：15s 宽限 → 离席+5min；处置无「换 Agent」项
- 服务器进程重启后可恢复同一房间；已开局则续同一 run；宕机期间离席钟冻结
- 终局后主机可「继续对局」同码重开；客人自动进入新对局
- 恢复失败有明确文案且须作废旧房后才能开新房

### 验收清单（建议，不挡规格完工）

- 两台物理机 + 公网联通
- 域名 + HTTPS 反代后全流程可跑

## Out of Scope

- 多房制并行、强账号体系、匹配服。
- 联机版任何 Agent 功能；本机版任何房间功能。
- 加入链接/地址+房间号手动加入 UI（接口层兼容 `/join?code=`）。
- 强制 TLS（域名接入前）；移动端 Safari 专项。
- 扩展角色、热座、纯观战席。
- 重做策划桌或规则内核。
