# 定义房间与远程座位的领域语言

Type: grilling
Mode: HITL
Status: resolved
Blocked by: none

## Question

在保留「对局（Match）」既有含义的前提下，局域网大厅中的「房间」、远程人类座位控制器、加入/占座等概念应如何写入 `CONTEXT.md` 的 ubiquitous language，才能既满足联机规格叙述，又不与现有将「房间」列为 Match 之 Avoid 的约定冲突？

## Answer

在根目录 [`CONTEXT.md`](../../../CONTEXT.md) 中切开对局与联机容器，并补齐控制器与占座/离席词汇：

- **对局** 禁止用「房间」作同义；**房间** 是局域网会话容器（一房至多一局）；**大厅** 是房间开局前的筹备阶段。
- **主机** 是运行权威服务并创建房间的进程/机器角色，不是座位控制器；主机侧人类座位仍用 **本地人类**。
- 座位控制器种类：**本地人类**、**远程人类**、Agent。「客人」「加入」不作正式术语；进入房间后绑定空人类位叫 **占座**。
- **房间号** 为弱门禁短码。**离席** / **回席** 描述远程人类暂时无法决策与认回原座，不等于淘汰。**座位凭证** 用于回席，不是会话 Cookie，不进权威对局状态。
