# 回合计时器、房间设置与观战

联机对局需要真实游戏的时间压力与容量冗余；表现层需要完整的外观与反馈体系。

## 背景

联机版流程能跑通，但存在三处体验硬伤：

1. **对人类座位没有任何决策时限**。响应窗口与行动阶段无限等待：一名玩家挂机，全桌只能等 5 分钟离席软超时后再由房主手动处置。真人局的节奏必须由权威服务兜底。
2. **轮询全量拉取**。`GET /matches/current` 每次返回完整 SeatView（含全部 projectedHistory），6 人长局多房时带宽/CPU 随历史长度线性放大（2 核 1.6G 云机）。
3. **满员/进行中的房间把后来者拒之门外**。无观战路径，朋友只能干等。

另外服务器侧 `matchId = match-${Date.now()}` 存在同毫秒撞号风险（rooms 主键冲突 → 502）。

## 决策

- **回合计时器（权威侧）**：房间新增 `turnTimeLimitSec` 设置（0=不限时，默认 60），仅大厅/续局阶段可由主机修改。权威服务在每次对局状态推进后为「当前欠决策的座位」武装一个 `setTimeout`；到期未决策则由服务器以该座位身份提交自动决策（响应窗口→放弃，行动→收入，证明→放弃证明，揭示→按合法决策第一项，交换→按合法决策第一项），走与人类决策完全相同的 `submitHumanDecision` 路径（事件、持久化、投影一致）。自动决策通过响应负载的 `autoDecision` 字段暴露给表现层做「超时」提示，不进领域事件。缺度暂停（离席阻塞推进）时定时器顺延重排。服务器重启恢复后按满时长重排。
- **增量轮询**：`GET /matches/current` 支持 `?since=<stateVersion>`；状态未变时只回 `{ unchanged: true, stateVersion, absences, pausedForAbsenceSeatId, turnDeadline }` 轻量载荷，历史不再随轮询线性重复传输。
- **观战**：`GET /matches/current?spectate=1` 允许无座位凭证的访问者获取**剥离私有态**的只读投影（hiddenCharacters 清空、legalDecisions 清空、`spectator: true` 标记）。加入页对「对局进行中」的房间提供「观战」入口。观战是只读投影，不产生任何座位凭证。
- **容量**：房间上限 10→20；新增惰性回收的定时清扫（5 分钟间隔、unref），空房不再只在下次建房时被回收。`matchId` 改用 `crypto.randomUUID()`。
- **表现层（web-desk / web）**：角色牌换为内联 SVG 卡面（五角色各有专属纹章与配色）+ 统一牌背；WebAudio 合成音效（点击/确认/金币/发牌/揭示/质疑/淘汰/胜利等，零音频资源文件）；桌面改为绒面椭圆桌 + 宫廷牌库 + 钱币堆的舞台化布局；大厅重设计（座位圆环、快捷人数、邀请复制、时限设置）；统一 toast 取代顶部错误条；清除开发术语泄漏（v{stateVersion}、本地人类/远程人类）。

## 备选

- WebSocket 推送：当前规模（≤20 房 × ≤7 客户端）下 1.5s 增量轮询足够，WS 需要会话与心跳双通道改造，收益不成比例；保留为后续演进。
- 客户端计时、超时由客户端自动提交：被否决——时限必须是权威语义，客户端时钟不可信且离席判定会双重触发。
- 领域层新增 timeout 事件：被否决——自动决策本质是一次合法座位决策，复用现有事件流不污染领域语言。
