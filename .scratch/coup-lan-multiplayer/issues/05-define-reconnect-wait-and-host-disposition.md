# 钉死远程座位重连、等待与主机处置策略

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 03

## Question

在「浏览器座位重连令牌 + 断线等待重连 + 超时后主机处置」已定的前提下，令牌生命周期、等待态 UI/对局时钟行为、默认软超时，以及超时后主机可选处置（踢出、换本机 Agent、技术中止等）的精确规则应如何写入规格，才能保证对局中可续玩且不出现无人能推进的死局？

## Answer

- **离席判定**：实时通道断开后先有 **15 秒宽限**（显示重连中，不因该座暂停）；宽限结束仍未恢复 → 标记 **离席**，启动 **5 分钟**软超时。座位卡显示离席与剩余等待时间。
- **暂停**：若正轮到该座决策，对局在该决策点暂停；若未轮到，其他座位可继续，直到下一次需要该座决策时再暂停。
- **主机处置**（等待期内可提前打开；软超时结束后必须选择）：①继续等待（再开一段 5 分钟）；②将该座改为本机 Agent（配置须就绪，作废旧座位凭证）；③技术故障中止整局；④规则淘汰该座。
- **规则淘汰**：强制揭示该座全部剩余面朝下影响力并淘汰，钱币回库；作废座位凭证；公开记录标明由主机因离席处置导致。
- **座位凭证**：对局中软超时本身不使凭证过期（待主机处置期间仍可回席）；回席成功则轮换新凭证；换 Agent / 规则淘汰 / 技术中止 / 终局 / 房间解散时作废。「继续等待」只重置倒计时，不换凭证。载体与绑定见 [核验多客户端会话…](03-verify-lan-session-and-reconnect-token.md)（HttpOnly、房间+座位）。
