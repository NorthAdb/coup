# ADR-0012：公网部署加固与空房回收语义

日期：2026-09-05 ｜ 状态：已采纳

## 背景

三款游戏已在公网云服务器长期运行。上线前审计（平台栈 + 三游戏全流程）发现：
单机/局域网时代安全的假设在公网上不成立，且部分房间生命周期路径永不回收。
逐项核对后确认以下问题真实存在（部分平台化前就有，平台化如实继承）：

1. `GET /api(/<game>)/room-recovery` 匿名可访问：枚举全部存续房号（含座位与
   阶段），等于绕过房号限速门禁（ADR-0007 的房号即弱门禁模型）直接广播。
2. `POST …/room-recovery/abandon` 仅需会话：任何持会话者凭 4 位房号即可
   对 `restored`（活）房间触发 `technicalAbort`，是开放的杀局通道。
3. brass/splendor 房号查询无限速（仅 coup 开启），4 位房号可秒级穷举。
4. 匿名会话存储无上限：公网可慢性撑爆内存。
5. 两类房间永不回收，公网会逐步占满房间上限：
   - 大厅/续局阶段有客人占座但全部失联（大厅无心跳租约可依据）；
   - 对局阶段房主关闭浏览器（本地座位恒算在场），以及技术性中止后的
     「对局阶段但内存无对局」僵尸壳。
6. 欠决策座位离席会拆除回合计时器，但回席/心跳后无人重新武装——该回合
   失去超时代打保护，回席者可无限期思考（ADR-0008 语义缺口）。
7. 客人在大厅无法主动让座（只能等房主重开或空房回收）。
8. 座位凭证是会话级 Cookie：浏览器重启即丢失，客人被锁在自己已占的座位外。

## 决策

1. **恢复端点门禁**：恢复清单 GET 需要会话（前端 `fetchRecovery` 先
   `ensureSession` 再带 CSRF）；abandon 拒绝 `restored` 房间
   （409 `restored_room_active`），只允许清理 failed/migration 条目。
   活房间的退场交给空房回收或对局内处置，不提供「凭会话+房号杀局」。
2. **空房回收闭环**（`gameRoomStack.isRoomEmpty`）：
   - 大厅/续局/「对局阶段但内存无对局」一律按可回收，靠活跃度续命：
     任意 GET/POST 刷新 `emptySince`，页面有人轮询就不回收；
   - 对局中要求「全部远程座位离席 **且** 本地座位 10 分钟未见」
     （`LOCAL_SEAT_GONE_MS`；本地座位由 GET/POST `matches/current`
     以本地凭证刷新在场标记 `lastLocalSeen`）；
   - 空置时长从「首次观察到空房」起算（非最后活动时间），满
     `IDLE_ROOM_RECLAIM_MS`（30 分钟）即解散并 technicalAbort 本房 run。
3. **回席补武装**：新增 `ensureTurnTimer`（仅当计时器缺失时补武装），
   接入回席与心跳路径；不得无条件 `armTurnTimer`（会以 now() 重置
   deadline，等于无限顺延）。
4. **公网卫生**：会话存储上限 1 万（FIFO 驱逐）；brass/splendor 房号
   查询开启与 coup 相同的按 IP 限速（10 次未命中/分钟 → 429）。
5. **客人主动让座**：平台栈端点 `POST …/rooms/:code/seats/leave`，
   凭证即身份（无 seatId 段），仅大厅阶段、仅远程座位；让出即转开放
   占座、凭证作废、presence 清理。对局中的离开仍走离席/房主处置
   （本端点 409），不破坏对局完整性。三端大厅座位卡提供「让出座位」。
6. **座位凭证持久化**：座位 Cookie 全部下发点统一带
   `Max-Age=SEAT_COOKIE_MAX_AGE_SEC`（30 天），浏览器重启后仍可回席；
   回席/续局轮换时自动续期。会话 Cookie 保持会话级（无状态，丢失由
   前端自动重建）。localStorage 方案否决（XSS 可窃取令牌）。
7. **前端 404 语义**：三端大厅轮询 404 明确提示「房间已解散或已被
   回收」并退回首页，不再静默吞掉。

## 后果

- 测试基线 272 → 283（server 104 → 115）：idleReclaimApi 3、
  sessionStore 2、恢复鉴权 1、回席补武装 1、seatLeaveApi 4；
  改写 restored-abandon 与 brass 限速两条旧语义断言。
- 行为变化：长时间无人且无请求的房间（含重启后恢复但无人认领的）
  30 分钟后自动解散；客人重启浏览器不再丢座；客人可自助让座。
- 恢复清单不再匿名可读；活房间不可再被 abandon（前端本就只展示
  failed 条目，无 UI 回归）。
- 集成测试断言房间存活必须用 `GET /:code/presence`——`GET /:code`
  本身是活跃度信号，会重置空置计时（idleReclaimApi.test 踩过）。
- HTTP 探针坑：Fastify 对带 `content-type: application/json` 的空
  body 回 400；无负载请求不要带该头（`-d` 会隐式 POST）。
