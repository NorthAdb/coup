# 钉死主机重启后的房间与对局恢复边界

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 05

## Question

在「主机不可替代；进程消失后客人只能等待或放弃；主机重启后应可恢复未结束的局域网对局/房间」已定的前提下，恢复粒度（房间大厅 vs 已开局对局）、与现有 SQLite 快照恢复的关系、客人持令牌重新附着的步骤，以及无法恢复时的失败表现应如何写入规格？

## Answer

- **恢复粒度**：大厅与已开局对局均持久化、均可恢复。SQLite（或同库扩展表）保存活动房间：房间号、座位槽配置、占座绑定、座位凭证哈希；若已开局则关联未结束对局 run。主机重启后进入恢复后的同一房间，而非空白新建。
- **与现有快照恢复的关系**：主机进程崩溃/重启 = **继续同一局 run**（同一 `matchId`、同一事件序号）。本机 MVP 的「从快照开恢复运行」（新 run、`resumedFromMatchId`）仍只用于 `technical_abort`，不用于主机重启。大厅无对局时只恢复房间记录。
- **客人重新附着**：主机不可达时客人页提示等待并周期性重试原 LAN Origin；主机恢复且 Origin 未变时，用既有座位凭证 Cookie 自动回席。若端口/IP 变化导致 Origin 变化：客人打开主机展示的新加入链接；服务端以房间号 + 座位凭证校验（Cookie 为主，必要时同源粘贴辅路径，见 [核验多客户端会话…](03-verify-lan-session-and-reconnect-token.md)）。回席成功轮换新凭证。
- **离席时钟**：权威服务未运行期间**冻结**离席软超时；不把宕机时长计入 5 分钟。主机恢复后各相关座先再给短宽限（沿用 15 秒），其后规则同 [钉死远程座位重连、等待与主机处置策略](05-define-reconnect-wait-and-host-disposition.md)。
- **Agent 座位**：对局/大厅中的 Agent 槽配置保留；重启后重绑 CLI 适配器并能力探测。未就绪时在需要该座决策处暂停，主机可重新检测或改配，或技术中止；**不**因重启本身强制揭示淘汰。
- **恢复失败**：记录损坏、缺关键绑定或凭证表无法校验时，主机显式「无法恢复上一房间」，须选择「放弃并开新房间」（作废旧房间号与凭证；未结束 run 标废弃/技术中止类终态）后才能创建新房。客人重试失败或凭证被拒 → 提示房间已失效可离开。禁止静默用新空白房顶替旧房间号。
- **端口**：恢复后仍按 [钉死房间码格式与加入链接形态](04-define-room-code-and-join-link.md) 尝试监听（默认 8787、占用则回退）；实际地址写入邀请 UI，供 Origin 已变的客人使用。
