# 10 — 主机模式监听与房间邀请

**What to build:** 首页三入口可选本机对战、创建房间或加入房间。创建房间后服务进入主机模式：监听可被局域网访问的地址（默认尝试 8787，占用则回退并展示实际端口），枚举非 loopback 局域网 IPv4 并允许手选，生成 4 位房间号与可复制的 `/join?code=` 加入链接。客人打开加入链接（或手填地址+房间号）能确认连上该主机上的房间；禁止仅房间号加入。本机对战仍只绑定 loopback。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 首页有本机对战 / 创建房间 / 加入房间三个入口，且本机开局与大厅不混用同一表单
- [x] 创建房间后主机模式监听非 loopback；UI 展示房间号、加入链接，多网卡可手选展示 IP；无候选时不填 127.0.0.1
- [x] 客人经完整加入链接，或「地址 + 房间号」进入并能确认房间存在；仅房间号被拒绝
- [x] 本机对战路径仍仅 loopback，行为不回归

## Answer

实现主机模式绑定与房间邀请垂直切片：

- `startServer`：`local` 仍 `127.0.0.1`；`host` 绑 `0.0.0.0`，启动时可 8787 占用回退；**运行时**重绑固定 8787（供客户端发现）。
- `POST /api/hosting/enter` 先响应再重绑；`POST /api/rooms` 要求已在主机模式；LAN IPv4 枚举/默认/手选；加入链接 `/join?code=`。
- 网页三入口（指挥台 B）；建房后导航 LAN Origin 再发房间号；加入页拒仅房间号。

已知后续：切回 loopback/解散房间的完整往返（文案已标明）；启动期 host 模式端口回退与运行时发现的差异。
