# 汇总 MVP 规格与验收边界

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 05, 06, 07, 08, 09

## Question

哪些可观察的功能、质量、兼容性和失败场景标准足以证明该 MVP 规格可以交给开发执行？最终规格应如何组织，才能完整引用前置决策而不重复或遗漏它们？

## Answer

最终交付物是索引型规格 [`spec.md`](../spec.md)：产品一句话、决策索引表、可勾选验收清单与建议实施顺序；细节只链接前置票据与研究报告，不复述全文。

### 组织方式

- 权威细节留在各自票据；`spec.md` 负责“能不能开工”与“怎样算做完”。
- Agent 策略/人格/牌力评测已划出本轮范围，见 [定义 Agent 策略配置与可玩质量](11-define-agent-strategy-and-quality.md)。

### 验收边界摘要

- **环境**：Windows 10/11；一条命令启动；`127.0.0.1`；Chrome/Edge 硬门槛；桌面浏览器视口适配；不要求手机端。
- **开局**：2–6 人、逐座位 CLI/模型、进页探测、全部就绪才开局、记住上次配置、本机 CLI 登录态。
- **对局**：基础版规则与确定性状态机；策划桌 UI；规则介绍；克制亮牌/补牌动效。
- **Agent**：`SeatView`/`SeatDecision`、禁工具、45 秒有界重试、技术中止可恢复。
- **数据**：SQLite 快照+事件；事件列表回放；从快照继续。
- **不验收**：牌力、局域网、原版美术、跨平台安装包。

完成本清单即可认为规格已可交给开发执行；实施本身不在本地图内。
