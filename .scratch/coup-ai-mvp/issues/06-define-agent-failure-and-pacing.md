# 定义 Agent 失败处理与回合节奏

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 04, 05

## Question

当 Agent 输出非法决策、超时、CLI 崩溃、权限受阻或模型不可用时，对局应如何重试、降级、暂停或退出？正常思考时长、流式反馈和动画节奏如何配合，才能兼顾可靠性与观感？

## Answer

Agent 决策采用有界的两次尝试；不使用自动出牌、人工代打或技术性淘汰作为兜底。无法取得合法决策时，本次对局运行以“技术故障中止、无胜者”结束，并允许用户修复配置后从故障前快照创建新的恢复运行。

### 决策生命周期

每次决策依次经历：

1. `queued`：等待该座位成为唯一当前决策者；
2. `thinking`：调用对应 Agent 适配器；
3. `validating`：解析并对照 `SeatView.legalDecisions` 校验；
4. `accepted`、`retrying` 或 `failed`。

首次尝试的硬截止时间为 30 秒；只有可恢复错误才重试一次，第二次最多 15 秒。总等待上限为 45 秒，不因 provider 输出活动或流式 token 自动延长。

每次尝试使用独立 `requestId`。重试沿用同一 `matchId`、`stateVersion` 和完整座位投影；前一次迟到的响应即使格式合法也必须丢弃。只有通过全部协议与领域校验的决策才能改变权威状态。

### 错误分类

可恢复、计入一次重试的错误：

- 达到本次截止时间；
- Agent 子进程意外退出，或 OpenCode 服务出现一次可重新建立的会话错误；
- 短暂网络、provider 或 rate-limit 错误，且明确重试等待不超过剩余 15 秒预算；
- 空输出、JSON 无法解析、JSON Schema 不匹配；
- 命令类型、目标或参数不在当前 `legalDecisions` 中。

第二次提示可以包含结构化错误类别和再次提供的合法选择，但不能把第一份原始响应拼入不受信任的系统指令，也不能扩大权限。

不可恢复、立即故障中止而不盲目重试的错误：

- CLI 未安装、版本或协议不受支持；
- 认证失效、缺少凭据、计费不可用；
- 所选 provider 或模型不存在或被组织策略禁止；
- 适配器无法落实“全部工具禁用”，或模型发起需要批准的工具权限请求；
- 会话隔离、私有信息投影或进程监管不满足安全约束；
- SQLite 无法提交已接受决策所需的原子事务。

### 中止与恢复

- 两次尝试后仍没有合法决策时，本次运行记录 `technical_abort`，胜者为空；不得把故障 Agent 当作按规则淘汰。
- Agent 决策被接受并持久化前，领域状态不变，因此故障恢复点是发出该次 `SeatView` 前最后提交的快照和事件序号。
- 原中止运行及脱敏错误事件保持不可变。用户修复 CLI、认证或模型配置后，可以从恢复点创建新的运行；新运行拥有新标识并重新请求该座位决策。
- 恢复不会复用已失败的原始 Agent 会话，也不会恢复或展示其私有原始输出。
- 用户始终可以主动中止本局；主动中止同样无胜者，但错误类别与技术故障分开。

### 用户可见反馈

- 浏览器只显示座位、provider/模型显示名、已等待时间，以及“准备中、思考中、校验中、正在重试、调用失败”等有限状态。
- 不流式展示 token、提示词、标准错误原文或模型推理过程。
- 可展开诊断只包含脱敏错误类别、尝试次数、耗时、CLI 版本和可操作建议，不包含 `privateState`、原始提示或原始响应。
- 首次尝试失败进入重试时明确提示，但不要求人类玩家介入。

### 对局节奏

- 默认提供“平衡”节奏。即使 Agent 瞬间返回，也保留最短可感知思考反馈，并按领域事件顺序播放声明、质疑、阻挡、证明、揭示和结算。
- 提供整局“快速模式”，仅缩短非必要等待和动画停顿；不能省略规则事件、改变响应顺序或提前提交下一次决策。
- 服务端权威状态可以先于视觉演出完成，但 Agent 编排层在浏览器确认关键演出已入队前不发起下一次 Agent 调用；浏览器失联时暂停编排，而不是自动推进。
- 演出确认设有限时，避免界面 bug 永久挂起；超限后发送完整投影供浏览器恢复。该限时属于表现层，不计入 Agent 的 45 秒决策预算。
- 具体最低思考展示时间、各类动画时长和快速模式倍率由“原型化核心对局体验”决定，不写入领域状态。
