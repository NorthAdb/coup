# 确定局域网演进边界

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 03, 05

## Question

AI-first MVP 必须在哪些状态所有权、消息协议、身份和进程边界上避免本机专用耦合，才能让后续局域网多人复用游戏核心，而不要求本轮提前实现房间发现、联网与断线恢复？

## Answer

本轮不实现局域网。未来局域网假设为**主机权威 + 创建房间 / 输入房间号加入**，交互参考常见桌游网页大厅（创建房间、房间号输入、进入房间、可选最近房间），视觉不必照搬参考站。

### 未来假设

- 一台主机运行权威引擎、持久化与全部 Agent 适配器。
- 其他人用浏览器加入；Agent 只跑在主机上。
- 支持本地人类、远程人类与主机 Agent 同桌混搭。
- 主机“创建房间”得到房间号；其他人输入房间号加入。大厅可另有查看规则、最近房间等，但不属于本轮交付。
- 本机 AI-first 开局仍使用已定稿的配置页，不套用房间隐喻；房间流程只留给联网版。

### MVP 必须遵守的硬性边界

- `packages/domain`、命令/事件协议与座位投影不依赖 `127.0.0.1`、本机用户名、浏览器 Cookie 或“唯一本地玩家”。
- 座位通过可替换控制器抽象：`local-human`、`agent`，并预留 `remote-human`；MVP 只实现前两种。
- REST/WebSocket 载荷按座位身份工作；本机会话只是传输凭证，不得进入权威 `MatchState`。
- Agent CLI、进程监管与本机认证探测留在主机服务内，不泄漏进领域状态或共享协议字段。
- 持久化以对局与事件为中心；不把 loopback 端口、房间发现细节或本机路径写进权威状态。
- 传输层与 Agent 适配器可替换；未来加入房间服务时复用同一领域核心与座位投影。

### MVP 明确不做

- 不监听 `0.0.0.0`，不实现 mDNS/局域网发现、房间码发放、传输加密、远程身份认证、断线重连占座。
- 不在本轮添加空的房间/发现接口桩；那些作为后续联网专题单独设计。
- 不能通过“把当前服务改绑公网接口”冒充局域网版本。
